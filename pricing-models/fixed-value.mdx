## Overview

A **Fixed Value** charge applies a pre-determined, flat amount for a specific period or as a one-time event — regardless of usage, volume, or transaction counts. Typical uses: a monthly subscription fee, an annual platform fee, or a one-time integration fee.

Because the amount doesn't depend on usage, a Fixed Value charge doesn't require transaction file uploads or usage metrics to calculate.

$$
\text{Calculated Charge} = \text{Fixed Configured Amount}
$$

Subject to pro-ration rules or validity periods, where applicable.

---

## Example

### SaaS scenario: platform access fee

A platform charges the same access fee regardless of how much a customer stores.

| Base Item | Fixed Amount |
|---|---|
| **Platform Access Fee** | INR 50,000 / month |

With no variables to resolve, the calculation is a direct lookup:

| Usage in the Period | Pricing Logic | Final Charge |
|---|---|---|
| Any volume | Constant — Calculated Charge = Fixed Amount | **INR 50,000** |

## Configuration

**Core Fields**

- **Pricing Type** — `Fixed Value`
- **Currency** — billing currency (e.g. `INR`, `USD`, `EUR`)
- **Item Master** — product/service this charge maps to (e.g. `Platform Subscription Fee`)
- **Fixed Amount** — the flat fee amount (e.g. `50,000`)

**Cadence & Validity**

- **Cadence Type** — `One-time` or `Recurring`
- **Cadence Period** *(Recurring only)* — `Monthly`, `Quarterly`, `Annually`
- **Step** — interval multiplier (`1` with `Monthly` triggers every month)
- **Valid From** — start date of charge eligibility
- **Charge Ends On / Occurrences** — end date, or a fixed number of billing cycles (e.g. `12 occurrences`)

## Real-Life Example

### Scenario: SaaS enterprise platform access

ACME Payments India Pvt Ltd pays a flat monthly subscription fee for Enterprise Platform access.

| Field | Value |
|---|---|
| Charge Name | Monthly Enterprise Platform Subscription |
| Customer | ACME Payments India Pvt Ltd |
| Plan | Enterprise Plan FY26 |
| Item Master | Platform Subscription Fee |
| Pricing Type | Fixed Value |
| Currency | INR |
| Fixed Amount | 50,000 |
| Cadence | Recurring — Monthly, Step: 1 |
| Valid From | 2026-04-01 |

At the end of each billing cycle (e.g. April 30, 2026), the charge bypasses usage calculation entirely:

$$
\text{Calculated Charge} = \text{INR } 50{,}000
$$

## Validation

<AccordionGroup>
  <Accordion title="Negative amounts">
    The fixed amount must be greater than or equal to 0. Negative values fail validation.
  </Accordion>
  <Accordion title="Validity dates">
    The billing run date falls within the Valid From and Charge Ends On window.
  </Accordion>
  <Accordion title="Cadence alignment">
    The selected cadence matches invoicing terms, so charges generate on schedule.
  </Accordion>
</AccordionGroup>
